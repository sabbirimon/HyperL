# Licence scope and history

The 2026-11-02 native-model adapter, original JAX decoder, authenticated fleet
scheduler/audit and original Cauchy erasure codec are newly covered Community/
Enterprise additions. External llama.cpp remains MIT; JAX and its dependencies
retain their own grants. No upstream engine source or models are copied into
HyperL, and earlier HyperL Apache grants remain unchanged.

The pre-transition tree is commit
`67b30e09741f4bba1672a891644fc73abb1f9855` ([source](https://github.com/sabbirimon/HyperL/tree/67b30e09741f4bba1672a891644fc73abb1f9855)).
HyperL material offered there under Apache 2.0 keeps those grants. Published
tags/releases through `v0.1.0-alpha.5` are not replaced or relabelled. The complete
previous root text is preserved at [Apache-2.0.txt](Apache-2.0.txt).

The new root licence offers newly covered additions under HyperL Community and
Enterprise License 1.0. It cannot withdraw permissions already granted for the
same material. Changing LICENSE, a version string or a header does **not** make
previously Apache-licensed implementation newly restricted. Enterprises may keep
using that earlier implementation and lawful forks under Apache's conditions.
The fee condition depends on new rights genuinely covered by the new licence.

Unchanged Apache-covered foundation files and original OpenCL/Metal bridges
retain their Apache notices. New modifications must state their actual licence
and preserve earlier notices. The separate existing Meshlit Apache port is
unaffected. Future ports of newly covered changes need an explicit compatible
grant; do not silently copy them into a project claiming all source is Apache.

Dependencies remain separate: Kotlin/coroutines/serialization/Gradle/FlatLaf
are Apache 2.0; RSyntaxTextArea is BSD-3-Clause; fonts are OFL 1.1. Bundled OpenJDK
retains GPL-2.0-with-Classpath-Exception and component notices/source obligations.
System vendor SDKs/drivers and external libraries are not relicensed. Preserve
complete upstream notices and applicable source/source-offer terms.

Git authorship is not an adjudication of ownership. Review each import and
contribution; a commit does not prove employer consent, a contributor agreement
or patent clearance.

The development version advances to alpha.6 to distinguish the transition from
immutable alpha.5 assets. No new release or signing claim is made. Old assets
are neither overwritten nor remotely restricted.
